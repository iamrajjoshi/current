## Design preferences

- Don't add decorative gradients, glows, simulated glass, or ornamental shadows to the app or website. Use solid surfaces, typography, spacing, and functional selection states.
- Keep native macOS materials and controls; let the operating system own their appearance. Don't recreate them with custom effects.
- Avoid promotional empty-state copy, repeated labels, decorative numbering, and unnecessary cards or pills. Use realistic notes in visual reviews.

## Releases

- Releases are manual only. Use the `Release` GitHub Actions workflow (`.github/workflows/release.yml`) with a `version` input like `0.1.0`.
- PRs and pushes should not create app releases. The regular `CI` workflow is the PR/push validation path.
- The release workflow builds `Current.app`, packages `Current-<version>.zip`, creates a GitHub Release at `v<version>`, and updates the Homebrew cask.
- Release artifacts are unsigned and not notarized for now. macOS may show normal unsigned-app first-launch friction.
- The app repository is public so Homebrew can download GitHub Release artifacts without authentication.

## Homebrew

- Homebrew tap: `github.com/iamrajjoshi/homebrew-tap`.
- Cask path in the tap: `Casks/current.rb`.
- Install command: `brew install --cask iamrajjoshi/tap/current`.
- The cask is generated by `scripts/update-homebrew-cask.sh`; update that template when changing cask metadata.
- `HOMEBREW_TAP_TOKEN` must be configured as an Actions secret on `iamrajjoshi/current`. Use a fine-grained token scoped only to `iamrajjoshi/homebrew-tap` with `Contents: Read and write`.
- Keep the cask `desc` Homebrew-friendly. Do not include the platform name such as `macOS`; `brew style --cask iamrajjoshi/tap/current` rejects that.
- Do not add `zap` entries for `~/Documents/Current`; that is user note data.
